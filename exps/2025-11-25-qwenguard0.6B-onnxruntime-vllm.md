# ONNX Runtime vs vLLM Performance Comparison Summary

## ⚠️ IMPORTANT NOTES

1. **Model Format Issue**: ONNX model conversion attempted with `--dtype bf16`, but the model appears to still be in FP32 format, not BF16 as intended.

2. **Memory Constraints**: ONNX Runtime experiments experienced Out of Memory (OOM) issues when batch size ≥ 8, limiting scalability testing.

3. **Configuration Differences**: 
   - ONNX: Tested with batch sizes (1, 2, 4, 8) using ONNX Runtime
   - vLLM: Tested with concurrency levels (1, 2, 4, 8) using FP32 dtype with prefix caching disabled for fair comparison

4. **Accuracy Discrepancy**: Significant accuracy gap observed - ONNX achieves 38-46% accuracy while vLLM maintains 78-80% accuracy. This suggests potential issues with ONNX model conversion or inference pipeline.

5. **ONNX Performance Degradation with Batch Size**: ONNX Runtime shows **negative scaling** - throughput decreases from 4.48 samples/s (BS=1) to 1.05 samples/s (BS=8), representing a 76% performance drop. This is highly unusual as batch processing should typically improve throughput efficiency. **Something must be off** with the ONNX batch processing implementation, configuration, or memory management.

## Summary & Recommendations

### Performance Summary

1. **Single Request Performance**: ONNX Runtime shows better raw performance for single requests (19% higher throughput, 16% lower latency)

2. **Scalability**: vLLM significantly outperforms ONNX when handling multiple concurrent requests, with positive scaling characteristics

3. **Accuracy**: vLLM demonstrates substantially higher accuracy (78-80% vs 38-46%), which is critical for production use

4. **Resource Efficiency**: vLLM handles higher concurrency without OOM issues, while ONNX experiences memory constraints at batch size ≥ 8

### Recommendations

1. **For Production Use**: **vLLM is recommended** due to:
   - Significantly higher accuracy (78-80% vs 38-46%)
   - Better scalability with concurrent requests
   - More stable performance characteristics
   - No memory constraints at tested levels

2. **ONNX Optimization Needed**: If ONNX is required, investigate:
   - Model conversion accuracy issues (46% vs 80% suggests conversion problems)
   - Batch processing implementation (negative scaling indicates inefficiency)
   - Memory optimization for larger batch sizes
   - Verify BF16 conversion is actually working

3. **Use Cases**:
   - **vLLM**: Recommended for production deployments requiring high accuracy and concurrent request handling
   - **ONNX**: May be suitable for single-request scenarios with strict latency requirements, but accuracy issues must be resolved first
